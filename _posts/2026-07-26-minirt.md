miniRT는 C로 구현한 CPU 레이트레이서입니다. 카메라에서 광선을 생성하고, 기하 primitive와의 교차점을 구한 뒤 조명과 그림자를 계산하는 전체 과정을 직접 구현했습니다.

![miniRT rendered scene](/assets/img/projects/minirt/result.png)

## Ray Tracing Engine

- 구, 평면, 원기둥, 삼각형과의 ray intersection
- mirror surface를 위한 제한 깊이의 recursive reflection
- 광원별 visibility를 검사하는 shadow ray
- 가장 가까운 교차점과 material을 선택하는 hit pipeline

## Phong Lighting

표면의 최종 색은 세 가지 조명 성분을 조합해 계산합니다.

- **Ambient:** 직접광이 없는 영역의 기본 밝기
- **Diffuse:** Lambert cosine law 기반 확산광
- **Specular:** view와 reflection vector를 이용한 highlight

## Camera

FOV를 기준으로 화면 pixel마다 camera ray를 생성합니다. local, world, camera space 변환을 구성하고 keyboard 입력으로 카메라 위치와 방향을 실시간 조작할 수 있게 했습니다.

## SIMD Optimization

ray tracing에서 반복되는 vector와 matrix 연산을 여러 `float` 단위로 처리하기 위해 SSE/AVX intrinsic을 적용했습니다.

- `__m128`에는 `xyzw` 네 성분을 담아 4개의 `float`를 병렬 연산
- `__m256`에는 8개의 `float`를 담아 16개 원소의 matrix를 두 묶음으로 처리
- dot product는 성분별 곱셈과 horizontal reduction을 intrinsic으로 수행
- aligned load를 사용할 수 있도록 vector와 matrix 메모리의 시작 주소를 정렬

```c
typedef struct __attribute__((aligned(64))) s_matrix
{
    float m[16];
} t_matrix;
```

`t_matrix`의 데이터 크기는 `16 × sizeof(float)`, 즉 64바이트입니다. `aligned(64)`는 구조체의 시작 주소를 일반적인 x86 cache-line 경계에 맞춰 matrix 하나가 경계를 걸치지 않도록 합니다. SSE aligned load는 16-byte, AVX aligned load는 32-byte 정렬이 필요하므로 64-byte 정렬은 두 조건을 모두 만족하지만, AVX 명령 자체가 64-byte 정렬을 요구하는 것은 아닙니다.

이 선언은 데이터 배치만 보장합니다. 실제 병렬 처리는 `__m128`·`__m256` register에 값을 load하고 연산하는 intrinsic 코드에서 이루어집니다. 동적 할당 메모리도 같은 정렬 조건을 지켜야 하며, 정렬을 보장할 수 없는 주소에는 unaligned load를 사용해야 합니다.

### Scalar/SIMD Microbenchmark

실제 `vector_dot`, `transform`, `concatenate` 함수와 scalar reference를 같은 입력으로 실행하는 standalone benchmark를 작성했습니다. 결과가 허용 오차 안에서 일치하는지 먼저 검사하고, 동일한 수학 연산량을 처리하는 데 걸린 시간과 처리량을 CSV로 출력합니다.

Ryzen 7 7800X3D, GCC 6.3, `-O3`, 2,000,000회 실행을 5번 반복한 중앙값입니다. scalar reference는 compiler auto-vectorization을 꺼서 packed intrinsic과 비교했습니다.

| Operation | Scalar | SIMD | 상대 성능 |
| --- | ---: | ---: | ---: |
| 4D dot product | 7.92 ns | SSE 20.20 ns | 0.39× |
| 4×4 matrix × vector | 10.27 ns | AVX2 7.12 ns | 1.44× |
| 4×4 matrix × matrix | 117.72 ns | AVX2 9.61 ns | 12.25× |

행렬×행렬 연산은 packed lane을 충분히 활용해 큰 차이가 났고, 행렬×벡터는 1.44배 개선됐습니다. 반면 짧은 dot product는 함수 호출과 `_mm_dp_ps` latency가 실제 산술보다 커 SSE가 오히려 느렸습니다. SIMD 적용 여부를 자료형만 보고 결정하지 않고 호출 단위와 instruction overhead까지 측정해야 한다는 점을 확인했습니다.

```bash
make profile PROFILE_ITERATIONS=5000000
```

## 해결한 문제

### 유한 원기둥 교차

무한 원기둥의 측면 교차와 위·아래 뚜껑 교차를 별도로 계산했습니다. 측면 교차점은 높이 범위로 clipping하고, 모든 후보 중 가장 가까운 양의 `t`를 선택했습니다.

### SIMD Memory Alignment

32-byte 정렬을 요구하는 AVX aligned load에 조건을 충족하지 않는 주소를 전달하면 잘못된 메모리 접근으로 이어질 수 있습니다. 구조체와 동적 할당 주소의 정렬을 보장해 aligned load의 전제 조건을 맞췄고, 정렬이 불확실한 경로는 unaligned load를 사용하도록 구분했습니다. 64-byte 정렬은 matrix 크기와 cache-line 배치를 고려한 layout 선택입니다.
