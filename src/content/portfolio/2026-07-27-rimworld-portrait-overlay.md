## 요약

- **선택한 폰을 전신 초상화로 표시하고 위치·크기·대상 필터를 조정하는 HUD 모드 배포**
- **기존 초상화 캐시를 재사용하되 전역 렌더 설정과 자원 수명을 호출 경계 안에 격리**
- **RimWorld 1.6 지원과 Steam 창작마당 구독자 2,104명·평가 96% 긍정 확보**

RimWorld에서 여러 정착민을 번갈아 지시할 때는 작은 하향식 화면만으로 현재 선택한 캐릭터의 외형을 구분하기 어렵습니다. 게임에서 캐릭터를 뜻하는 ‘폰’을 정면 전신 초상화로 보여 주는 이동식 패널을 HUD에 추가해, 선택과 명령 흐름을 바꾸지 않고 현재 대상을 바로 확인할 수 있게 했습니다.

담당 범위는 선택 상태부터 초상화가 그려지는 경로 분석, C# 렌더링·설정 구현, 호환성 처리와 Steam 창작마당 배포입니다. 패널 위치와 크기, 확대 정도, 배경, 장비 표시, 동물·기계 생명체·포로 등 표시 대상을 사용자가 조정할 수 있습니다.

## 바뀔 수 있는 내부 호출 형식에 고정 결합하지 않기

- **선택한 해결법:** `PortraitsCache.Get`의 오버로드를 런타임에 찾고, 매개변수의 타입·이름·기본값을 읽어 인자를 구성했습니다. 게임의 기존 초상화 렌더러와 캐시를 이용해 선택한 폰의 전신 이미지를 HUD 텍스처로 가져옵니다.
- **근거:** 전신 초상화에 필요한 렌더링을 별도로 복제하면 의상·장비와 폰 외형을 계산하는 게임 규칙도 함께 따라가야 합니다. 기존 경로를 재사용하면 원본 렌더 결과를 유지할 수 있지만, 내부 메서드의 정확한 시그니처에 컴파일 시점부터 결합됩니다. 필수 인자는 타입으로 식별하고 선택 인자는 이름과 기본값으로 채워 이 결합을 한곳에 모았습니다. 대신 정적 타입 검사의 범위가 줄어드는 비용을 감수하고, 메서드를 찾지 못하거나 결과가 없으면 빈 초상화로 돌아가도록 실패 경계를 뒀습니다.

## 실시간 갱신이 전역 렌더 상태를 오염시키지 않게 하기

- **선택한 해결법:** 초상화를 그리기 전후로 해당 폰의 캐시를 무효화하고, 캐시에 남은 `RenderTexture`는 게임 내부 정리 메서드로 해제했습니다. 무기와 머리 장비 표시를 위해 바꾼 전역 환경설정은 렌더링 동안만 유지하고 `finally`에서 원래 값으로 복원했습니다.
- **근거:** 자세와 방향이 바뀌어도 캐시 키가 그대로면 이전 초상화가 남을 수 있고, 캐시 항목만 제거하면 GPU 렌더 텍스처의 수명이 끊기지 않습니다. 반대로 게임 전체가 공유하는 환경설정을 바꾼 채 반환하면 다른 초상화 화면까지 영향을 받습니다. 캐시 데이터와 렌더 자원을 함께 정리하고 전역 상태를 예외 경로에서도 복원해, 선택 폰의 갱신은 허용하면서 변경의 범위를 한 번의 렌더 호출로 제한했습니다. 이 방식은 실시간 모드에서 캐시 재생성과 렌더 비용이 늘어나는 대신 최신 자세와 다른 UI의 상태 보존을 우선합니다.

## 다른 모드의 Pawn 타입에서 생긴 실패를 HUD 밖으로 번지지 않게 하기

- **선택한 해결법:** 차량형 `Pawn`은 상속 계층의 타입 이름으로 판별해 렌더링 전에 제외했습니다. 그 밖의 커스텀 타입에서 초상화 렌더링 예외가 나면 타입별로 한 번만 경고하고 빈 초상화로 대체합니다.
- **근거:** 다른 모드가 만든 객체는 기본 `Pawn` 선택 조건을 통과해도 RimWorld의 초상화 렌더러가 요구하는 구성 요소를 모두 갖췄다고 보장할 수 없습니다. 지원 범위를 억지로 넓히기보다 실패를 해당 초상화 한 건에 가두면 선택과 명령을 포함한 원래 HUD는 계속 사용할 수 있습니다. 차량형 폰을 표시하지 못하는 제한을 받아들이고, 호환되지 않는 타입 하나가 매 프레임 예외와 로그를 반복하는 상황을 막았습니다.

2026년 8월 29일 확인 기준 Steam 창작마당에서 현재 구독자 2,104명, 고유 방문자 10,452명을 기록했습니다. 평가 84개 중 81개가 긍정적이어서 긍정 평가 비율은 96%입니다. 현재 호환 범위는 RimWorld 1.6이며, 내부 API 변화에 대한 자동 회귀 검증은 소스에 포함되어 있지 않습니다.
