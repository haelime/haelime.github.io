컴퓨터로 작업하거나 공부할 때, 누군가 조용히 함께하고 있다는 감각을 느끼고 싶어 개발했습니다.

빗소리나 바람 소리, Lo-fi 음악을 함께 듣고, 악기를 연주하거나 공유 캔버스에 그림을 그릴 수 있습니다.

**내 입력은 로컬에 먼저 반영하고, 다른 사람과 공유할 정보는 성격에 맞게 나누어 전송.** 연주는 현재 눌린 음을, 그림은 순서가 있는 선분 기록을 공유하도록 구성했음.

연주는 새 상태로 현재 음을 맞출 수 있지만, 그림은 이전 선분이 빠지면 최종 결과가 달라짐. 이 차이에 맞춰 반응성과 상태 복원을 함께 다루는 것이 핵심 작업이었음.

## 연주: 입력은 즉시, 공유는 최신 상태로

### 내가 낸 소리는 Host 응답을 기다리지 않기

`NetworkInstrumentPerformer`에서 입력 즉시 로컬 악기를 재생하고, 상태 전송을 별도로 처리했음. Host 응답을 받은 뒤 재생하면 내 입력에도 통신 지연이 붙기 때문. 다른 Client의 소리는 Client → Host → Client 경로를 거쳐 전달됨.

로컬 오디오 대기 시간을 줄이기 위해 씬 시작 전에 256 sample DSP buffer를 요청하고, 장치가 변경을 거부하면 기존 설정을 유지하도록 처리함. 버퍼 크기에 대한 요청이며 입력부터 실제 소리가 나기까지의 전체 지연을 보장하는 값은 아님.

### 누름과 뗌을 하나의 상태로 묶기

**누름과 뗌을 별도 이벤트로 보내지 않고, 현재 눌린 입력을 비트 마스크로 묶어 전송.** 뗌 메시지가 유실되면 음이 계속 남을 수 있고, 과거 이벤트를 순서대로 재전송하면 최신 연주가 늦어질 수 있어 현재 상태를 기준으로 맞추도록 했음.

양쪽 Client가 가진 악기 샘플을 각자 재생하고, Steam의 `UnreliableNoDelay`로 상태를 전달함. 악기 종류, 연주 여부, 입력 마스크와 식별 정보, 순서 번호를 포함한 애플리케이션 패킷은 18바이트. 전송 계층의 헤더는 제외한 크기임.

| 상황 | 처리 |
| --- | --- |
| 입력이 바뀜 | 전체 입력 상태를 전송하고 수신 측에서는 달라진 음만 재생에 반영 |
| 연주 중 상태 패킷이 유실됨 | 기본 0.05초마다 전체 snapshot을 다시 보내 현재 상태를 맞춤 |
| 중복되거나 늦은 패킷이 도착함 | 순서 번호로 걸러 이전 상태가 최신 상태를 덮지 않도록 처리 |
| 최신 상태가 더 이상 도착하지 않음 | 0.3초 후 원격 연주 상태를 만료시켜 음이 계속 남는 것을 방지 |

이 방식은 최신 연주 상태를 전달하는 데 초점을 둠. 누름과 뗌 사이의 패킷이 모두 유실된 짧은 음은 복원하지 못하며, 모든 Client가 같은 시각에 음을 재생하는 합주 동기화까지 제공하지는 않음.

Host는 캐릭터 소유권, 악기와 입력 슬롯의 유효성을 검사하고 재입력 간격을 적용한 뒤 다른 Client로 전달함. 로컬 반응과 별개로 공유 상태의 검증은 Host에 유지했음.

## 그림: 손끝에는 즉시, 공유에는 선분 기록

### 그리기와 전송 주기를 분리

**선은 로컬 캔버스에 먼저 그리고, 전송할 선분은 모아서 처리.** Host 승인을 기다리면 손끝보다 선이 늦고, 좌표가 바뀔 때마다 전송하면 드래그 빈도만큼 메시지가 늘어나기 때문.

기본 0.08초가 지나거나 32개가 쌓이면 Host로 전송하고, 드래그를 끝낼 때 남은 선분도 보냄. 로컬 화면은 입력에 맞춰 갱신하면서 전송 호출을 묶는 구조. 다른 사람에게 보이는 그림에는 배치 대기 시간이 추가됨.

### 픽셀 대신 그리는 명령을 공유

그림은 선분 명령으로 저장해 뒤늦게 참가한 Client도 재생할 수 있도록 구성했음. 기본 캔버스인 256 × 192 RGBA32의 전체 픽셀은 압축 전 192 KiB이므로, 변경마다 이미지를 보내는 대신 그리는 데 필요한 정보를 전달함.

- 시작점과 끝점 좌표 4개를 `ushort`로 양자화.
- 색상 인덱스, 반지름과 도구를 각각 `byte`로 표현.
- 선분 필드 데이터는 11바이트. 실제 메시지에는 RPC와 목록 동기화 정보가 추가됨.

Host는 그리기 권한, 속성 범위와 Client별 입력 빈도를 검사한 뒤 승인된 선분을 Server 쓰기 권한의 `NetworkList`에 추가함. 각 Client는 누적 기록을 순서대로 캔버스에 적용해 입장 시점이 달라도 그림을 복원하도록 연결했음.

## 확인 범위와 남은 작업

구현 코드에서 로컬 선반영, 연주 상태의 전송과 만료, Host 검증, 그림 배치와 기록 재생 경로를 확인했음. Edit Mode 테스트에는 잘못된 패킷 거부, 순서 번호의 중복/역전/순환, 좌표 양자화와 권한 검사 등이 정의되어 있음.

현재 근거는 **구현 코드와 테스트 정의까지**이며, 테스트 실행 결과와 원격 오디오 지연 측정값은 확보하지 않았음. 일부 검사는 소스와 직렬화 설정을 대상으로 하므로 실제 두 Client의 통신 검증과 구분됨. 유실 환경에서의 짧은 음 누락, 실제 출력 지연과 공동 그림의 일치는 두 Client로 확인할 항목.

장시간 공동 작업에는 두 가지 보완이 남아 있음.

- 최대 8,192개 선분 이후에도 입력을 받기 위한 기록 압축.
- Host가 거절한 로컬 선분을 승인된 기록에 맞춰 되돌리는 화면 보정.
