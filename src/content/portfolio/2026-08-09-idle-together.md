컴퓨터로 작업하거나 공부할 때, 누군가 조용히 함께하고 있다는 감각을 느끼고 싶어 개발했습니다.

빗소리나 바람 소리, Lo-fi 음악을 함께 듣고, 악기를 연주하거나 공유 캔버스에 그림을 그릴 수 있습니다.

함께 노는 기능에서도 내 입력은 바로 반응하고, 다른 사람에게는 연주와 그림이 빠짐없이 전달되는 것을 중요하게 생각했습니다.

- **로컬 반응:** Host 응답을 기다리지 않고 악기 재생과 그리기를 먼저 반영
- **연주 동기화:** 입력 순서와 시각을 전달하고, 재생 버퍼로 짧은 음과 재타격 보존
- **공유 그림:** Host가 확정한 그림과 미승인 획을 분리하고, 압축 스냅샷으로 참가 시점의 그림 복원

## 연주: 짧은 음과 재타격 보존

### 내 소리는 입력 직후 재생

Host 응답을 받은 뒤 소리를 내면 내 입력에도 통신 지연이 붙습니다. 로컬 연주와 원격 전달을 분리해, 적어도 내 조작은 바로 들리도록 했습니다.

- `NetworkInstrumentPerformer`에서 입력 직후 로컬 악기 재생, 상태 전송은 별도 처리
- 씬 시작 전에 256 sample DSP buffer 요청, 장치가 거부하면 기존 설정 유지
- 다른 사람의 연주는 Client → Host → Client 경로로 전달

256 sample은 오디오 버퍼 설정값이며, 입력부터 스피커 출력까지의 전체 지연 측정값은 아닙니다.

### 최신 상태만 보내던 방식에서 입력 전이 보존으로

처음에는 현재 눌린 키를 비트 마스크로 묶어 unreliable로 전송했습니다. 다음 상태로 누르고 있는 음은 복원할 수 있지만, 짧게 누른 음이나 재타격 사이의 뗌이 유실되면 그 연주 자체가 사라지는 문제가 있었습니다. 최신 상태를 맞추는 것에 더해, 누름과 뗌의 순서를 보존하도록 전송 방식을 바꿨습니다.

- 입력 변경, 연주 시작/종료, 악기 전환을 **reliable ordered**로 전송
- Steam은 `ReliableNoNagle`, 일반 Netcode transport는 reliable RPC 사용
- 각 Client의 악기 샘플을 재생하므로 오디오 대신 악기 종류, 눌림 상태, 순서 번호와 시각 전달
- `NetworkManager.ServerTime.Time`을 기록하고, Host 중계 시에도 원래 연주 시각 유지
- 애플리케이션 패킷 **26바이트**, 연주 중 50ms 주기로 현재 상태 재전송
- Host에서 소유권, 악기와 입력 슬롯, 시각, 패킷 빈도 검사 후 전달

패킷 크기에는 RPC와 전송 계층의 헤더를 포함하지 않았습니다.

### 도착 간격 대신 연주 시각에 맞춰 재생

패킷을 도착하는 대로 재생하면 네트워크의 흔들림이 리듬에도 반영됩니다. 원격 연주에는 작은 버퍼를 두고, 조금 더 기다리더라도 음 사이의 간격을 유지하도록 했습니다.

- 기본 80ms의 원격 재생 버퍼, Inspector에서 20~200ms 범위로 조절
- `연주 시각 + 버퍼 지연`을 기준으로 상태 적용, 대기 상태는 최대 128개
- 늦은 패킷이 묶여 도착하면 첫 상태의 지연에 맞춰 남은 재생 시각을 이동
- 수신 중단 시 음과 대기 큐 정리, 순서 번호는 유지해 오래된 중복 패킷의 재생 방지

통합 테스트에서는 Host가 패킷을 모두 받았는데도 재타격이 보이지 않는 경우를 확인했습니다. Unity 프레임이 정체된 뒤 누름, 뗌, 재타격을 같은 Update에서 처리한 것이 원인이었습니다.

- 서로 다른 시각의 상태가 한 프레임에 몰리면 남은 큐의 재생 시각을 뒤로 이동
- 같은 타임스탬프의 동시 입력은 함께 처리
- 프레임 정체 후에도 누름 → 뗌 → 재타격이 구분되는지 회귀 테스트로 확인

이 처리는 추가 지연을 허용하는 선택입니다. reliable 재전송 중에는 뒤의 음도 기다릴 수 있고, 현재 재생은 Update 단위이므로 DSP 샘플 단위의 정확한 타이밍까지 보장하지는 않습니다.

### 악기별 재생 정책 분리

악기마다 입력을 해석하는 방식이 달라도 같은 전송 경로를 사용할 수 있도록 구성했습니다.

- **다성:** 여러 입력의 음을 함께 유지
- **단성:** 마지막으로 누른 음을 우선 재생하고, 떼면 아직 누른 이전 음으로 복귀
- **오카리나:** 구멍, 반구멍, 숨 입력을 비트 마스크로 조합해 음높이 결정
- 플레이어별 악기 인덱스와 재생 버퍼 분리, 프리팹에 작성한 AudioSource 풀 사용

현재 실제 카탈로그에 연결된 악기는 오카리나 1종입니다. 세 재생 정책은 기존 프리팹의 복사본으로 검증했으며, 피아노나 기타 콘텐츠를 추가한 상태는 아닙니다.

## 그림: 바로 그리고, 승인된 결과로 맞추기

### 로컬 획과 확정된 그림 분리

Host 승인을 기다리면 손끝보다 선이 늦게 나타납니다. 로컬에는 먼저 표시하되, 권한이나 속도 제한으로 거부된 획이 내 화면에만 남지 않도록 했습니다.

- Host가 확정한 픽셀 데이터와 미승인 로컬 획을 별도 보관
- 기본 80ms 또는 32개 선분을 기준으로 배치 전송, 드래그 종료와 창을 닫을 때 남은 선분 전송
- Host에서 그리기 권한, 도구, 팔레트, 반경과 사용자별 입력 빈도 검사
- 처리한 배치마다 revision 증가, 승인한 획과 처리 완료 번호 전달
- Client는 처리된 로컬 획을 제거하고, 확정 그림 위에 아직 미승인인 획만 다시 적용

동시에 그린 선이 겹치면 Host가 확정한 순서가 최종 결과입니다. 승인 과정에서 로컬에 먼저 보이던 선의 겹침 순서가 바뀔 수 있습니다.

### 오래 그려도 늘어나지 않는 복원 데이터

기존에는 선분을 `NetworkList`에 계속 쌓아 늦은 참가자가 다시 그리도록 했습니다. 이 방식에는 8,192개 선분 상한이 있어, 현재 그림의 스냅샷을 복원 기준으로 바꿨습니다.

- 평소에는 시작점/끝점, 팔레트, 반경, 도구로 구성한 **11바이트 선분 데이터** 전송
- 확정된 그림은 픽셀당 팔레트 인덱스 1바이트로 저장, 기본 256 × 192에서 압축 전 **48 KiB**
- 늦은 참가자에게는 Deflate로 압축한 현재 그림을 4,096바이트 이하의 조각으로 전달
- 조각의 순서와 길이, 압축 해제 크기와 팔레트 범위를 검사한 뒤 복원
- 승인 지연이나 revision 누락 시 스냅샷으로 재동기화, 미승인 획은 최대 512개로 제한

전체 선분 이력을 저장하지 않으므로 오래 그려도 복원할 기록이 계속 늘어나지 않습니다. 현재 범위는 세션 내 공유이며, 디스크 저장과 undo/redo는 포함하지 않았습니다.

### Shift로 직선 그리기

Rust의 [Painting Line Tool](https://rust.facepunch.com/news/shipshape)을 참고해, 자유롭게 그리는 붓과 함께 직선 도구를 추가했습니다.

- Shift+드래그 중 본인 화면에만 직선 미리보기 표시
- 마우스를 놓을 때 선분 확정 후 공유, 취소 시 원래 그림 복원
- 기존 붓, 지우개, 팔레트와 Host의 손님 그리기 허용 설정 유지

## 검증과 남은 확인

**Unity 6000.6.0f1의 관련 테스트 39개 통과.** 패킷 형식뿐 아니라 실제 loopback UTP 연결에서 Host, Guest와 늦은 참가자의 동작을 확인했습니다.

- 잘못된 패킷 거부, 순서 번호의 중복/역전/순환 검사
- 짧은 음과 재타격, 늦은 패킷 묶음, 프레임 정체 시 재생 상태 보존
- 다성/단성/오카리나 운지 정책과 프리팹에 작성된 오디오 계층 검증
- 9,000회 그린 픽셀 데이터의 압축/복원 일치 확인
- 실제 RPC를 통한 그림 승인, 권한 거부 후 로컬 획 제거, 늦은 참가자의 그림 일치 확인

통신 검증은 한 Unity 프로세스 안의 여러 NetworkManager와 loopback 연결에서 진행했습니다. 실제 Steam 회선의 합주 출력 지연과 음질, 장시간 동시 작업, 그림 스냅샷 전송이 연주 지연에 주는 영향은 추가 측정이 필요합니다.
