miniRT는 과제 제약상 GPU 사용이 금지된 환경에서 C로 구현한 CPU 광선 추적기입니다. 카메라에서 광선을 생성하고, 기본 도형과의 교차점을 구한 뒤 조명과 그림자를 계산하는 전체 과정을 직접 구현했습니다.

## 광선 추적 엔진

- 구, 평면, 원기둥, 삼각형과의 광선 교차
- 거울 표면을 위한 제한 깊이의 재귀 반사
- 광원별 가시성을 검사하는 그림자 광선
- 가장 가까운 교차점과 재질을 선택하는 교차 판정 흐름

## Phong 조명

표면의 최종 색은 세 가지 조명 성분을 조합해 계산합니다.

- **환경광:** 직접광이 없는 영역의 기본 밝기
- **확산광:** Lambert 코사인 법칙 기반 확산광
- **정반사광:** 시선과 반사 벡터를 이용한 강조광

## 카메라

시야각을 기준으로 화면 화소마다 카메라 광선을 생성합니다. 로컬, 월드, 카메라 좌표계 변환을 구성하고 키보드 입력으로 카메라 위치와 방향을 실시간 조작할 수 있게 했습니다.

## SIMD 최적화

광선 추적에서 반복되는 벡터와 행렬 연산을 여러 `float` 단위로 처리하기 위해 SSE/AVX 내장 함수를 적용했습니다.

- `__m128`에는 `xyzw` 네 성분을 담아 4개의 `float`를 병렬 연산
- `__m256`에는 8개의 `float`를 담아 16개 원소의 행렬을 두 묶음으로 처리
- 내적은 성분별 곱셈과 수평 합산을 내장 함수로 수행
- 정렬 불러오기를 사용할 수 있도록 벡터와 행렬 메모리의 시작 주소를 정렬

SIMD를 적용할 때 먼저 본 것은 레지스터 폭이 아니라, 값을 레지스터에 준비하고 재배치하는 비용을 몇 개의 결과에 나눌 수 있는가였습니다. 서로 독립인 값을 각 연산 칸에 배치하고 같은 연산을 반복할 때 처리 폭을 활용할 수 있습니다. 반대로 네 성분을 곱한 뒤 결과 하나로 합치는 짧은 내적은 수평 합산 비용의 비중이 커서 SIMD가 유리하다고 단정할 수 없습니다.

4×4 행렬 곱은 같은 행과 열 데이터를 여러 결과에 재사용하므로 AVX 레지스터를 채우기 좋습니다. 행렬과 벡터 곱도 네 결과를 함께 계산할 수 있습니다. 이처럼 연산의 자료 흐름을 먼저 정리한 뒤, 묶을 수 있는 구간에만 내장 함수를 적용했습니다.

```c
typedef struct __attribute__((aligned(64))) s_matrix
{
    float m[16];
} t_matrix;
```

`t_matrix`의 데이터 크기는 `16 × sizeof(float)`, 즉 64바이트입니다. `aligned(64)`는 구조체의 시작 주소를 일반적인 x86 캐시 라인 경계에 맞춰 행렬 하나가 경계를 걸치지 않도록 합니다. SSE 정렬 불러오기는 16바이트, AVX 정렬 불러오기는 32바이트 정렬이 필요하므로 64바이트 정렬은 두 조건을 모두 만족하지만, AVX 명령 자체가 64바이트 정렬을 요구하는 것은 아닙니다.

이 선언은 데이터 배치만 보장합니다. 실제 병렬 처리는 `__m128`과 `__m256` 레지스터에 값을 불러와 연산하는 내장 함수 코드에서 이루어집니다. 동적 할당 메모리도 같은 정렬 조건을 지켜야 하며, 정렬을 보장할 수 없는 주소에는 비정렬 불러오기를 사용해야 합니다. 현대 x86에서 비정렬 불러오기가 언제나 느린 것은 아니지만, 캐시 라인 경계를 걸치거나 정렬 불러오기 명령의 전제를 어기면 비용이나 오류가 발생합니다. 정렬은 넓을수록 좋은 값이 아니라 실제 자료 크기와 사용하는 명령에 맞춰 선택해야 합니다.

### 스칼라와 SIMD 성능 비교

실제 `vector_dot`, `transform`, `concatenate` 함수와 스칼라 기준 구현을 같은 입력으로 실행하는 독립형 성능 측정 프로그램을 작성했습니다. 결과가 허용 오차 안에서 일치하는지 먼저 검사하고, 동일한 수학 연산량을 처리하는 데 걸린 시간과 처리량을 CSV로 출력합니다.

Ryzen 7 7800X3D, GCC 6.3, `-O3`, 2,000,000회 실행을 5번 반복한 중앙값입니다. 스칼라 기준 구현은 컴파일러 자동 벡터화를 꺼서 SIMD 내장 함수와 비교했습니다.

| 연산 | 스칼라 | SIMD | 상대 성능 |
| --- | ---: | ---: | ---: |
| 4차원 내적 | 7.92 ns | SSE 20.20 ns | 0.39× |
| 4×4 행렬 × 벡터 | 10.27 ns | AVX2 7.12 ns | 1.44× |
| 4×4 행렬 × 행렬 | 117.72 ns | AVX2 9.61 ns | 12.25× |

행렬과 행렬 연산은 SIMD 처리 폭을 충분히 활용해 큰 차이가 났고, 행렬과 벡터 연산은 1.44배 개선됐습니다. 반면 짧은 내적은 결과 하나를 만들기 위한 `_mm_dp_ps`의 수평 합산과 함수 호출 경계 비용이 실제 산술보다 크게 작용해 SSE가 오히려 느렸습니다. 작은 함수에서는 명령 수를 줄였다는 사실보다 불러오기, 재배치, 합산, 반환까지 포함한 전체 경로가 중요합니다.

이 수치는 해당 CPU, 컴파일러, 최적화 옵션에서 직접 작성한 SIMD 코드와 자동 벡터화를 끈 스칼라 기준 구현을 비교한 결과입니다. 따라서 최신 컴파일러가 자동 벡터화한 코드보다 항상 빠르다는 의미는 아닙니다. 먼저 결과를 허용 오차로 검증하고, 대상 환경에서 반복 측정한 수치로 적용 여부를 결정했습니다.

현재 구현은 한 벡터나 행렬 내부의 성분을 묶는 방식입니다. 다음 최적화 후보는 여러 광선의 `x`, `y`, `z` 성분을 각각 연속 배치해 교차 판정을 한꺼번에 수행하는 광선 묶음 처리입니다. 다만 도형 종류와 재질에 따른 분기가 늘면 같은 레지스터 안에서도 실행 경로가 갈리므로, 자료 배치와 교차 판정 구조를 함께 바꿀 근거가 생길 때 적용할 영역으로 남겼습니다.

```bash
make profile PROFILE_ITERATIONS=5000000
```

## 해결한 문제

### 유한 원기둥 교차

무한 원기둥의 측면 교차와 위쪽 및 아래쪽 뚜껑 교차를 별도로 계산했습니다. 측면 교차점은 높이 범위로 잘라내고, 모든 후보 중 가장 가까운 양의 `t`를 선택했습니다.

### SIMD 메모리 정렬

32바이트 정렬을 요구하는 AVX 정렬 불러오기에 조건을 충족하지 않는 주소를 전달하면 잘못된 메모리 접근으로 이어질 수 있습니다. 구조체와 동적 할당 주소의 정렬을 보장해 정렬 불러오기의 전제 조건을 맞췄고, 정렬이 불확실한 경로는 비정렬 불러오기를 사용하도록 구분했습니다. 64바이트 정렬은 행렬 크기와 캐시 라인 배치를 고려한 자료 배치입니다.
