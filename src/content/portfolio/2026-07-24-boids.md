## Boid의 움직임 이해하기

각 개체가 이웃을 기준으로 움직이면서 새 떼나 물고기 떼의 움직임을 모방하도록 만드는 알고리즘입니다.

- **Separation:** 너무 가까운 이웃에게서 멀어짐.
- **Alignment:** 주변 이웃의 이동 방향에 맞춤.
- **Cohesion:** 주변 이웃의 중심으로 모임.

## GPU Boids, boid 계산 구현

**boid 상태의 계산부터 렌더링까지 GPU 메모리 안에서 연결.** 타일 단위로 이웃 데이터를 공유하고, 힘 계산과 상태 갱신을 분리해 갱신 전후의 데이터가 섞이지 않도록 구성했음.

Craig Reynolds의 Boids 규칙을 compute shader로 구현. 각 개체는 주변 이웃에서 조향력을 구한 뒤 속도와 위치를 갱신하고, 렌더링은 갱신한 상태를 직접 읽는 흐름.

### 이웃 데이터를 타일로 공유

개체마다 GPU 스레드를 할당하고, 이웃 데이터 256개를 그룹 공유 메모리에 올려 재사용하도록 구성했습니다.

각 스레드가 같은 데이터를 전역 메모리에서 반복해서 읽는 비용을 줄이기 위한 처리

공유 데이터를 읽기 전과 다음 타일로 교체하기 전에 동기화해, 계산 중인 데이터가 덮어써지지 않도록 했음.

**타일링으로 줄인 것은 메모리의 반복 읽기이며, 전체 이웃 검사의 O(N²)은 유지됨.** 16,384개를 전체 탐색하면 프레임당 쌍 검사는 268,435,456회. GPU에 옮겨 병렬 처리해도 개체 수가 두 배면 검사량은 네 배가 되는 구조임.

### 힘 계산과 상태 갱신을 분리

**모든 조향력을 계산한 뒤 위치와 속도를 갱신하도록 두 단계를 분리.** 이웃을 읽는 도중 다른 스레드가 위치를 바꾸면 이전 상태와 다음 상태가 섞일 수 있기 때문.

1. **ForceCS:** 현재 위치와 속도를 읽어 조향력을 별도 힘 버퍼에 기록.
2. **IntegrateCS:** 이웃 탐색이 끝난 뒤 힘 버퍼를 읽어 각 개체의 속도와 위치를 갱신. 최대 조향력, 최대 속도와 벽 회피를 적용하고 다음 상태를 계산함.

각 스레드가 자기 상태만 쓰더라도 다른 스레드가 그 상태를 읽는 중일 수 있음. 힘 버퍼와 실행 단계를 나눠 이 읽기와 쓰기 시점을 구분했음.

### CPU로 복사하지 않고 렌더링에 연결

갱신한 <code>ComputeBuffer</code>를 재질에 연결해 정점 셰이더가 위치와 속도를 직접 읽도록 구성함. <code>GetData()</code>를 통한 CPU 복사를 거치지 않고, <code>Graphics.DrawMeshInstancedIndirect()</code>로 boid을 그리도록 연결했음.

시뮬레이션 영역 전체를 하나의 bounds로 사용해 개체별 CPU 경계 갱신도 피함. 대신 개별 보이드 단위의 세밀한 컬링은 제공하지 않으며, 이 구조가 전체 프레임을 얼마나 줄였는지는 별도 측정이 필요함.
