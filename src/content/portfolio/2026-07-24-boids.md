## Boid의 움직임 이해하기

각 개체가 이웃을 기준으로 움직이면서 새 떼나 물고기 떼의 움직임을 모방하도록 만드는 알고리즘입니다.

- **Separation:** 너무 가까운 이웃에게서 멀어짐.
- **Alignment:** 주변 이웃의 이동 방향에 맞춤.
- **Cohesion:** 주변 이웃의 중심으로 모임.

## GPU Boids, boid 계산 구현

**Boid의 조향력 계산, 위치 갱신과 렌더링을 GPU 버퍼로 연결했습니다.** 개체마다 주변 이웃을 확인해야 하므로, 같은 데이터를 반복해서 읽는 비용과 병렬 갱신 중 상태가 섞이는 문제를 중심으로 처리 흐름을 구성했습니다.

### 이웃 데이터를 공유해 반복 읽기 줄이기

각 Boid는 자신의 위치와 속도를 기준으로 이웃을 판단하지만, 읽어야 할 이웃 데이터는 다른 Boid와 겹칩니다. 스레드마다 같은 데이터를 전역 메모리에서 가져오는 횟수를 줄이기 위해, 이웃을 256개씩 묶어 그룹 공유 메모리에 올렸습니다.

- GPU 스레드 하나가 Boid 하나의 Separation, Alignment, Cohesion 계산 담당
- 그룹의 각 스레드가 이웃 데이터 하나씩 적재하고, 256개 데이터를 함께 재사용
- `GroupMemoryBarrierWithGroupSync()`로 적재 완료 후 읽기 시작, 현재 타일을 모두 읽은 뒤 다음 타일로 교체

타일링을 적용해도 전체 이웃을 검사하는 **O(N²)** 구조는 유지됩니다. 예를 들어 16,384개를 전체 탐색하면 한 프레임의 반복 횟수는 약 2.68억 회입니다. 이는 자기 자신을 포함한 N² 계산값이며, 개체 수가 두 배가 되면 검사량은 네 배로 늘어납니다.

### 조향력 계산이 끝난 뒤 상태 갱신

이웃을 읽으면서 자신의 위치를 바로 갱신하면, 다른 스레드가 갱신 전후의 상태를 섞어 읽을 수 있습니다. 모든 Boid가 같은 시점의 위치와 속도를 기준으로 판단하도록 계산과 갱신을 두 커널로 나눴습니다.

1. **`ForceCS`:** 현재 위치와 속도를 읽어 조향력을 계산하고, 별도 힘 버퍼에 저장
2. **`IntegrateCS`:** 뒤이어 Dispatch해 저장된 힘과 벽 회피를 적용하고, 같은 상태 버퍼의 속도와 위치 갱신

힘 계산 단계에서는 위치와 속도를 바꾸지 않습니다. 이웃 탐색이 끝난 뒤 각 스레드가 자신의 상태만 갱신하므로, 다른 Boid의 읽기와 쓰기가 겹치지 않게 했습니다.

### 계산한 버퍼를 렌더링에 바로 연결

계산 결과를 매 프레임 CPU로 가져와 개별 Transform에 적용하면 데이터 복사와 CPU 갱신이 추가됩니다. 위치와 속도를 담은 `ComputeBuffer`를 렌더링 Material에도 연결해, 정점 셰이더가 직접 읽도록 했습니다.

- 인스턴스 ID로 해당 Boid의 위치와 속도를 읽어 메시 위치와 방향 결정
- `GetData()`로 상태를 복사하지 않고 `Graphics.DrawMeshInstancedIndirect()`로 그리기
- 군집 전체를 포함하는 하나의 `Bounds`를 전달해 렌더링 범위 지정

이 방식에서는 개별 Boid 단위의 세밀한 컬링을 제공하지 않습니다. 반복 읽기와 CPU 복사를 줄이는 실행 경로는 코드에서 확인했으며, 전체 프레임 시간의 개선량은 별도로 측정하지 않았습니다.
